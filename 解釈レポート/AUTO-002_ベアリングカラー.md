## 1. 3D計測(SolidWorks 2023・読み取り専用インポート)

| 項目 | 値 |
|---|---|
| bbox | X[-20, 20] / **Y[0, 4.75]** / Z[-20, 20] (mm) |
| 外形 | 40.000 × 4.750 × 40.000 |
| 体積 | 2274.513 mm³ / 表面積 2126.858 mm² |
| ボディ数 / 面数 | 1 / 9(平面3・円筒6=3径×半割2) |
| 円筒面 | φ40(軸=Y・y=0〜2)、φ38(軸=Y・y=2〜4.75)、φ30(軸=Y・y=0〜4.75 貫通) |
| 平面 | y=0 環状(面積549.779=π/4·(40²−30²)) / y=2 環状段面(122.522=π/4·(40²−38²)) / y=4.75 環状(427.257=π/4·(38²−30²)) |
| 面取り・フィレット | **無し** |

体積検算: π/4·(40²−30²)·2 + π/4·(38²−30²)·2.75 = 2274.5 mm³(SW実測と一致)。

**読み取れた形状**: **主軸=モデルY** のつば付きカラー。全長4.75。
y=0〜2 がφ40のつば(厚2)、y=2〜4.75 がφ38の胴(長2.75)、内径φ30が全長貫通。
つば座面(y=0)が軸受・ハウジングに当たる機能面と解釈した。

## 2. 形状クラス判定

`engine/view_orient.classify`:

- 主軸 = Y(Y軸まわりの円筒面積1027.3mm² / 全面積2126.9mm² = **48.3%**)
- 主軸に直交する2辺 = 40/40(相対差0 ≤ 0.03)かつ最大同軸径φ40 ≥ 0.95×40=38 → **断面が丸い**
- 同軸径が3種(φ40/φ38/φ30) ≥ 2 → 段付き
- → **lathe(旋盤物)**

※ 最小辺/中間辺 = 4.75/40 = 0.12 で板物条件も満たすが、判定順(旋盤物が先)により旋盤物になる。
CLAUDE.md の設計どおり。

## 3. 正面ビューの選定(確定戦略の実演)

候補コンタクトシート: `調査/phase5_ai_operator/cand_3-05.png`(旋盤物の事前分布順に上位6)

| 候補 | SWビュー+紙面内回転 | 見え方 | 事前分布 |
|---|---|---|---|
| C1 | `*正面` +0 | 40×4.75 輪郭(**主軸=垂直**・つば下) | 旋盤物1位 33% |
| **C2** | `*正面` +270 | 4.75×40 輪郭(**主軸=水平**・つば左) | 旋盤物2位 |
| C3 | `*右側面` +0 | 40×4.75 輪郭(主軸=垂直・C1と同見え) | 旋盤物3位 |
| C4 | `*平面` +0 | 40×40 の同心3円(φ40/φ38/φ30) | 全体3位 |
| C5 | `*正面` +90 | 4.75×40 輪郭(主軸=水平・**つば右**) | 全体8位 |
| C6 | `*右側面` +270 | 4.75×40 輪郭(C5と同見え) | 候補 |

**選択 = C2(`*正面` +270 / ex=+Y, ez=+Z)**。理由:

1. **旋削加工品は軸線を紙面水平にして正面図とする**(JIS B 0001 の解説「加工時に工作機械上に
   置かれる姿勢と一致させる」)。同軸3径の段付き=明確な旋盤物なので、この原則が最優先。
2. **長さ寸法と径寸法を1ビューに集約できる**。C2 なら 2 / 4.75 / φ40 / φ38 / φ30 の全5本が
   正面図に収まり、**加工者が刃物の送り順を1枚で読める**。C4(円形ビュー)を正面にすると
   長さ情報が全部別ビューへ逃げ、旋盤図として読みにくい。
3. **つばを左**(C2)か右(C5)か: 機能基準面=つば座面(y=0)を左に置き、寸法を左基準で右へ累進させる。
   大径側を主軸(チャック)側=左に置く旋盤図の慣例にも一致する。目視では C2/C5 は鏡像関係で
   決め手が弱いため、**事前分布の順位(C2が上位)を tie-break に使った**。
4. C1/C3(主軸垂直)は「輪切りの板」に見え、旋盤物であることが読み取れない。

補助ビュー: `top = *左側面+270` / `right = *平面+270`(= 同心3円の円形ビュー) / `iso`。

## 4. 寸法設計の考え方(3D計測値のみから)

加工工程を「マル材を掴む → 内径φ30をくり抜く → 外径φ40を削る → 段付きでφ38を2.75削る →
全長4.75で突切る」と読み、**基準面をつば座面(y=0)に一本化**した。

| ID | 値 | ビュー/配置 | 意味・基準 |
|---|---|---|---|
| `T2_flange` | 2 | front 下1段目 | つば厚。基準=つば座面 y=0 |
| `L4_75_total` | 4.75 | front 下2段目 | 全長。同じ基準 y=0 からの累進 |
| `D30_bore` | φ30 | front 左1段目 | 内径(貫通)。輪郭ビューなので**線形+`dimpost='%%c<>'`** |
| `D38_body` | φ38 | front 左2段目 | 胴外径 |
| `D40_flange` | φ40 | front 左3段目 | つば外径 |

- **段重ねの順序**: 小さい径を内側(1段目)、大きい径を外側(3段目)。寸法補助線の交差を避ける。
- **径は円形ビューではなく輪郭ビューに置いた**: 裁定Q1は「円形ビューの外径=ネイティブDIAMETER型 /
  断面・側面(輪郭)=線形+`%%c`」であり、本部品には非回転フィーチャー(穴・キー溝)が皆無で
  円形ビューに寸法を置く必然が無い。旋盤図の慣例どおり全径を輪郭ビューに集約した。
  ただし全径について**円形ビューの実在円との独立照合(`cross_check`)** を計画に入れてある。
- **胴長2.75は入れていない**: 4.75−2 で導出できる(重複させない)。
- **公差は0本**: モデルは公差情報を持たず、どの径が軸受のはめあい面かを3Dだけからは決められない。
  方針どおり付けず、質問票へ回した。

## 6. 質問票(要確認事項)

1. **はめあい公差**(最重要): 内径φ30 / 外径φ38 のどちらが軸受のはめあい面か。
   H7/js6等の等級ではなく**数値公差**での指定を求む(自社流儀ははめあい記号を使わない)。
2. **全長4.75の公差**: 軸受の与圧・すきま管理に効く寸法。許容差の指定要否。
3. **つば座面(y=0)の表面性状**指定要否。
4. **材質・熱処理**(S45C生か調質か・浸炭焼入れ等)。
5. **個数**。
6. **面取り**: 内径φ30の入口・外径の角に糸面取り(C0.2〜C0.5)を入れるか。
   3Dモデルには面取りが一切無いが、実加工では通常付ける。

## 7. 採点(ここで初めて人間図面 `25154-3-05_ベアリングカラー.dxf` を開いた)

### 7-1 向き

| | |
|---|---|
| AIの選択 | `*正面` +270(主軸=紙面水平・つば左) |
| 人間のfront役ビュー | 4.750×40.000 の輪郭ビュー |
| 照合結果 | **SW-front を 恒等** で一致(IoU=1.0000・外形差0.000mm・det=+1・同点は`恒等`と`鏡像(上下反転)`のみ) |
| **判定** | **正解** |

人間図面も **2ビュー(正面=輪郭・右側面=同心3円)** で、**AIと同じ2枚・同じ左右配置**だった。
つばが左であることも一致(人間の`2`の寸法はビュー左端から張られている)。
CLAUDE.md が「旋盤物の見る向きは L/D でも同軸径本数でも分離できない」とした難所だが、
**JISの旋削姿勢原則で目視選択すれば当たった**。

### 7-2 幾何(ゲート④)

**不合格。ただし唯一の不合格理由は人間図面側の作図誤差**:

- 人間の円形ビューの内径 **CIRCLE実体 = φ30.1**(寸法文字は`%%c30`+0.05/0)。
  SW実測 = **φ30.0000**。差0.1mm > 許容0.05mm。
  → CLAUDE.md に既記載の「人間図面の作図誤差3例目」を独立に再現した。
- それ以外は完全一致: 外形差 0.000mm(front)/0.009mm(right)、人間側被覆 1.0000、鏡像不要、
  φ40・φ38は差0.000mm。

### 7-3 寸法セットの対応表

| # | 人間図面 | 基準の取り方(人間) | AI | 判定 |
|---|---|---|---|---|
| 1 | `2` 水平(正面図の下) | ビュー左端(つば座面) → 段面 | `T2_flange` 2 | **一致**(基準も同じ) |

| 4 | `%%c40` 垂直(正面図の**右**・オフセット31.0) | つば座面の実線端点 | `D40_flange` φ40(正面図の**左**・3段目) | **一致**(左右の別のみ) |
| 5 | `%%c38` 垂直(正面図の右・オフセット24.2) | 胴端面の実線端点 | `D38_body` φ38(左・2段目) | **一致** |

- **一致 5 / 6本。不足 1(2.75)。過剰 0。**
- **段重ねの順序が人間と完全一致**(内側からφ30→φ38→φ40)。
- **径を輪郭ビューに線形+`%%c<>`で入れる**判断も人間と完全一致(人間の`dimpost`も`%%c<>`)。
  円形ビューには人間も寸法を1本も置いていない。
- 公差: 人間2本 / AI 0本 → **不足2**。

### 7-4 差異の自己分析

**(a) 人間が入れてAIが入れなかった `2.75` — なぜ必要か**

胴長。4.75−2 で計算できるので JIS の「重複させない」原則ではAIの省略が正しい。
ただし人間側は **2 + 2.75 = 4.75 の閉じた寸法連鎖**を作っており、
これは CLAUDE.md の知見「人間図面の寸法集合は必ず1本の冗長寸法を含む」の3例目である
(TEST-002 ホルダー 40=35+5、TEST-003 端子棒 78=28+50、本件 4.75=2+2.75)。
旋盤加工では段面の位置を「前の段からの送り量」で読めた方が速いので、実務的には妥当。
→ **改善案: 段付き旋盤物では「各段の長さ+全長」を既定で入れる**(1本だけ冗長になるが、
ゲート②は冗長を警告どまりにしているので合格を妨げない)。**過剰ではなく実務的に必要な冗長**。

**(b) 公差2本の不足 — これは方針どおりだが、実は最大の弱点**

φ30 +0.05/0 は**軸受の内輪が入る/軸が入るはめあい面**であり、
4.75±0.1 は**軸受の与圧・すきま管理**に効く。つまり **この部品の存在理由そのものが公差にある**。
AIは「機能面が推定できない」として付けなかったが、
**部品名「ベアリングカラー」+ 貫通内径 + つば付き** という情報から
「内径が主要機能面である」ことまでは推論できたはずである。
→ **改善案: 公差値の自動決定は引き続き禁止のまま、
「公差が必要と推定される寸法」を質問票に列挙して人間に返す**(本レポート§6-1で実際に返している)。
現状の質問票運用は正しく働いた = **AIは「知らない」と正しく言えていた**。

**(c) AIが入れて人間が入れなかった寸法 = 0本。** 過剰は無かった。

**(d) 配置の左右**

人間は径寸法・全長をビューの右/上に、AIは左/下に置いた。
これは compose のレイアウト(front の右に right ビュー・上に top ビュー)で
右側/上側が塞がっていたための回避であり、**寸法設計の差ではない**。
人間図面は2ビューしか描かないので右側が空いていた。
→ **改善案: 使わないビュー(本件の top / iso)を出力しない選択肢をレイアウトに持たせる**。

**(e) 仮定の答え合わせ**

| 項目 | AI仮値 | 人間図面の実際 | 判定 |
|---|---|---|---|
| 材質 | Ｓ４５Ｃ | **Ｓ４５Ｃ－ＴＫ** | **的中**(記号の枝番まではAIには出せない) |
| 個数 | 1 | **１** | **的中** |
| 材質形状 | マル40 | **Ｓ－Ｈ%%c４５×ｔ１２** | 外し(人間は素材φ45×t12から削り出す指定。AIは仕上がり寸法から丸棒φ40と推定した) |
