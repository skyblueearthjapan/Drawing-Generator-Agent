## 3. 計画作法ルールの有効性評価

追記した5つの作法(`app/prompts/plan_prompt.md`「❗計画の作法」)について、実測での効き目。

### 作法1 基準面チェーン(位置寸法は必ず1つの datum から連結する) — ★最も効いた

盲検の主因だった「孤立した寸法対の羅列」を、軸ごとに datum を決めた直列チェーンへ書き換えた。

| 部品 | 適用内容 | 位置未指定の変化 |
|---|---|---|
| 1-04 | X=中心線 / Z=左端面 / Y=ベース下面 を基準に7本追加 | **19 → 0** |
| 3-04 | 軸受穴中心線(X=0/Z=0)と中心平面(Y=0)を外形基準面へ連結する3本を追加 | X: **18 → 0**、Y: 10 → 8 |
| 6-02 | X=中心線から2本の寸法線に5本を直列で連ねた | X: **4 → 0** |

- **3-04が象徴的**: 追加したのは「軸受穴中心線→右端面 71」「同→上面 45」「中心平面→ボルト穴 17」の
  **たった3本**。これで X軸18ノードが一気に到達可能になった。
  盲検版は 全長142 / 全幅90 / ボルト穴間118 / 高さ34,58 と**外形の対寸法しか無く、
  穴系のノードが1つも基準に届いていなかった**。幾何は一意なのに不合格になる典型。
- **結論: ルールは有効。位置未指定は「計画の書き方」でほぼ全滅させられる**(41ノード中41ノード解決)。

### 作法2 穴群の位置指定(PCDは実ジオメトリと一致するときだけ) — ルールは正しいが救済力なし

- 5-04 の φ9×12(PCD142)は実測隣接角が **[12,18,12,78]×3 = 4個1組が120度おきに3群**、
  φ11×6 は [20,100]×3。**円周等分ではない**のでエンジンが注記を却下する(正しい挙動)。
  修理パスでは作法2に従い **PCD表記を括弧付きの参考情報へ降格**させた。
- 「等配でないものにPCDを書かない」というルールは守れたが、**代替手段(角度寸法)がエンジンに無い**ため
  未指定は減らない。**ルールの効果はエンジン開発待ち**。

### 作法3 正多角形は二面幅または対角を必ず入れる — ルールは正しいが**エンジンが受け取れない**

- 1-04 の六角座は**紙面内で任意角に回転**している。頂点間の軸平行距離を全ペア計算しても
  最大 ΔX=24.756 / ΔZ=27.666 で、二面幅24 にも対角27.712 にも 0.01mm以内で一致しない。
- 二面幅は対辺中点間の距離で、中点は実ジオメトリの特徴点でないので `snap` もできない。
- `direction` に角度を書けば対角27.712 を測れるが、
  `gate2_completeness` は角度が0/90度でない線形寸法を `oblique_dimension` として判定対象外に落とすため
  **幅として採用されない**。→ **エンジン未対応**(§4 E4)。

### 作法4 図枠ゾーンに寸法・注記・引出線を置かない — ★納品1件を直接生んだ

- 追記した**縦方向の予算式** `2×max(下側予約帯, 上側予約帯) + g ≤ 262 − 幾何合計高さ` が実務で機能した。
  ビュー群は**幾何だけ**が y=30〜292 の中央に置かれるので、上下の余白は必ず等分される。
- 実測した安全マージン: **寸法線位置(base)から外側へ最大 10.3mm** 描画実体が出る
  (文字が寸法線の外に出るケース)。垂直寸法は測定点の上下に **±3mm**。
  → 実運用は「above の base ≤ 281 / below の base ≥ 41」で見ておけば安全。
- 適用例:
  - **5-08**: 幾何193mm+A3の262mmで余白は上下23.75mmずつしか無く、below に3段積めば必ず表題欄に刺さる。
    Z寸法を「front下側2本(offset 11/19)・front上側1本(11)・top上側2本(11/19)」へ分散し、
    2×24.5+16.5=65.5 ≤ 69 を満たして**衝突0件**。
  - **6-02**(φ420・1:2): 上下余白26mmしか無いので**段積みが物理的に不可能**。
    5本のX位置寸法を **2本の寸法線に直列で連ねて**解決(1本の寸法線に複数寸法を並べるのは
    重なりが無い限り正当で、しかも作法1の直列チェーンと同じ形になる)。
  - **2-06**(φ222・1:1): 上下余白20mm。PCD参考寸法6本を削除して穴注記へ一本化し、
    厚み寸法を上下1本ずつへ分散。
  - **3-04**: 全高58の寸法枠が左上ノート欄(x≤115, y≥255)へ掛かるため測定位置を右端へ移し、
    引出線を右回りへ変更。
- **引出線ランディングの向き**は実害があった: 5-08 の穴注記は最後の折れ点でモデルX方向へ動かしており、
  平面図では**図面yの移動=垂直**になって図枠上端を突き抜けていた。
  「ビューごとにモデルのどの軸が図面x/yか」を `meta.json` で必ず確かめる、を作法に明記した。
- **結論: 20件あった図枠衝突が0件。レイアウト検証6/10→10/10。ルールは完全に有効**。

### 作法5 穴注記(φ既定・呼び径ちょうどの穴はМ表記を検討) — 副作用なしで適用できた

- キリ表記の残っていた6件(1-04/2-06/3-04/3-09/5-04/6-02)と、既納品の3件(4-07/4-12/7-06)を
  **φ(`%%c`)・全角の既定へ是正**。納品済み4件の注記は現在すべて `２－%%c１３` 形式。
- М表記は**「呼び径と±0.1mm一致 かつ 3個以上が円周等配」を満たすものだけ**に適用:
  4-07 `１２－Ｍ５ ＰＣＤ１２９` / 6-02 `４－Ｍ８ ＰＣＤ１４０` / 3-04 `４－Ｍ６深さ１２ ＰＣＤ９０` /
  3-09 `４－Ｍ６深さ１０ ＰＣＤ９０` / 5-04 `４－Ｍ６ ＰＣＤ４０` / 2-06 `４－Ｍ８深さ１６ ＰＣＤ１４５`。
- **懸念していた副作用(М表記にするとPCD穴群の検算が壊れる)は起きなかった**。
  `parse_hole_note()` はねじ注記から**呼び径と下穴径の両方**をカバー径にし、`ＰＣＤ` も別に拾うため、
  `find_pcd_groups()` の実ジオメトリ検算は従来どおり通る(4-07/6-02/3-04/3-09/5-04 で確認)。
- 条件を満たさないもの(単独穴・矩形配置4個・呼び径に無い径)は**φのままにして計画コメントに根拠を残した**:
  5-08 のφ10単独通し穴、1-04 のφ6×4矩形配置、3-04 のφ8×2、4-12/7-06 のφ5/φ6 など。
  **これらのМ/φ判定の当否は本パスでは検証できていない**(人間図面を見ないため)。次回盲検の観測項目。

   改善Aの図枠衝突検出では不合格になる状態だった)。巻き戻し時は**納品箱の複製も削除**する
   (検証を通っていない旧DXFが納品箱に残るのを防ぐため)。

### 残っている不具合・改善要望

1. **❗`retry` は台帳を更新しない**。巻き戻した依頼の台帳行は「不合格」「出力DXF=`生成/不合格/…`」の
   ままで、しかも `retry` が `生成/` を消すので **台帳のパスがダングリングになる**。
   → `retry` 時に台帳行の状態を「再試行のため巻き戻し」へ更新するべき。
2. **❗台帳に盲検時代の重複行が残っている**(1図番あたり3〜4行)。
   `upsert_ledger_row` は `依頼ID=` マーカー付きの行しか置換しないため、
   `generate_drawing.py` が直接書いた古い行(マーカー無し)が残り続ける。
   現在の正は**マーカー付きの10行**だが、読む人には見分けがつかない。
   → 履歴の掃除はデータ削除になるためディレクター判断を仰ぐ(本パスでは触っていない)。
3. **ゲート③(目視)が状態機械に無い**のは未解決。納品4件のPNGは生成済みだが誰も見ていない。
4. **尺度の自動提案が無い**のも未解決。6-02(φ420)は 1:2 でも上下余白が26mmしか無く、
   **尺度が寸法配置の可否を直接決める**ことが今回はっきりした。
   → bbox とビュー集合から「作法4の予算式を満たす最大の尺度」を提案する段があると計画が楽になる。
