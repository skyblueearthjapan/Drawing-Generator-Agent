# 教師STEP取り込み・投影・人間図面照合レポート(フェーズ2残課題)

実施日: 2026-08-10 / 環境: SolidWorks 2023 (`SldWorks.Application.31`) / Python + pywin32 / ezdxf 1.4.4
対象: 荏原「ラインマン200」工番25154 の製作部品 5点(バケットA 4点 + 非バケットA 1点)

---

## 0. 結論(先に)

| 問い | 答え |
|---|---|
| SW2023でSTEPを開けるか | **開ける。ただし `OpenDoc6` では開けない。`ISldWorks.LoadFile4` が唯一通る** |
| 単位はmmで入るか | **入る**。bbox・体積・円筒径が設計値と 0.001mm 未満で一致 |
| 既存 draw_pipeline はSTEPでそのまま動くか | **動かなかった**(3箇所)。最小修正で貫通(§5) |
| STEPの座標系は人間の「正面」と一致するか | **投影像そのものは完全一致(5/5部品でIoU 1.000・外形差0.000mm)。ただし「どの軸方向を正面に選ぶか」「紙面上の回転」は部品ごとにバラバラで、STEPの座標系をそのまま使うことはできない** |
| 鏡像(行列式-1)は必要か | **不要。5部品すべて det=+1 で一致。非対称部品(1-25走行LSドグ)で唯一解として恒等変換が確定** |
| フェーズ4量産検証は進められるか | **進められる**。ただし「正面ビューの選定」を形状から決める機構が必須(§7に提案) |

**一言でいうと**: STEPのジオメトリは人間図面と寸分違わない(**鏡像も歪みも無い**)。
足りないのは「その形をどの向きから見て紙に載せるか」という**ビュー選定**だけであり、
これはフェーズ3の作図計画側の仕事として明確に切り出せる。

## 1. STEPの開き方(実証済み手順)

### 1-1. 動いたAPI

```python
isd = sw.GetImportFileData(step_path)          # STEPなら IImportStepData が返る
doc, err = sw.LoadFile4(step_path, "r", isd, 0)  # err=0 / doc=IModelDoc2
```

- 戻り値は **`(IModelDoc2, error)` のタプル**。`error=0` で成功。
- 生成されるのは **未保存の部品ドキュメント**: `GetTitle()='1-18.SLDPRT'` / **`GetPathName()=''`**
- `GetModelViewNames()` は `*正面/*平面/*右側面/*等角投影` …10個が正常に返る(標準ビューは使える)

### 1-2. ❗動かなかったAPI(実測エラーコード)

| 呼び出し | 結果 |
|---|---|
| `OpenDoc6(step, swDocPART=1, Silent\|ReadOnly)` | `doc=None, error=2097152` (`swFileRequiresRepairError`) |
| `OpenDoc6(step, swDocPART=1, Silent)` | `doc=None, error=2097152` |
| `OpenDoc6(step, swDocIMPORTED_PART=6, Silent)` | `doc=None, error=1024` (`swInvalidFileTypeError`) |

→ `engine/generate_drawing.py` の「STEPパスが来ても OpenDoc6 に渡すだけで通る」という
**主張は誤りだった**(未実証のまま書かれていた)。実証の結果 STEP 専用経路が必要と判明。

### 1-3. ❗新しい罠(3つ・すべて実害あり)

**罠A: `CreateDrawViewFromModelView3` に STEPのパスを渡しても None が返る**

インポート部品は `GetPathName()` が空なので、ModelName に渡すべきものが無い。実測:

| ModelName | 結果 |
|---|---|
| STEPのフルパス | **None(ビューが作れない)** |
| `GetTitle()` = `'1-18.SLDPRT'` | **OK** |
| `""`(空文字) | OK(ただしアクティブ文書依存で危険。使わない) |

→ 対策: `OpenedDoc.model_name` プロパティを追加(インポート品は title、通常品は path)。

**罠B: `CloseDoc(title)` では未保存インポート部品が閉じられない**

`sw.CloseDoc('1-18.SLDPRT')` も `sw.CloseDoc('1-18')` も**無反応**(例外も出ずに開いたまま居座る)。
`sw.QuitDoc(title)`(=保存せず閉じる)で確実に閉じる。
※ `CloseAllDocuments(True)` でも閉じるが、ユーザーの文書まで閉じるので**安全規約違反。使用禁止**。

**罠C: `GetFirstDocument` + `GetNext` は全件列挙できない**

図面+部品の2件が開いている状態でも**1件目で `GetNext` が None になり1件しか返らない**。
安全確認(pre/post スナップショット)がこの列挙に依存していたため、
「自分が開いた分だけ閉じる」判定が壊れる寸前だった。
→ **`ISldWorks.GetDocuments()` を使う**(`dp.list_open_docs()` に集約)。

### 1-4. 安全規約の遵守状況

- 教師STEPは `LoadFile4` で読むだけ。**一切保存していない**(SLDPRT保存もSTEP上書きも無し)
- 全実行で `pre_open=[]` → `post_open=[]` → `leaked_docs=[]` を meta JSON に記録
- 図面→部品の順で閉じる(**図面が部品を参照している間は部品を閉じられない**ことを実測)
- 最終確認: `GetDocumentCount()=0` / `GetDocuments()=[]`

## 2. 単位・座標系の実態

### 2-1. 単位は mm で正しく入る

`GetBodyBox`(m)×1000 が設計値ちょうどになる。検算:

| 部品 | bbox size (mm) | 体積 (mm³) | 解析値との照合 |
|---|---|---|---|
| 1-18 クッション | 25.000 × 25.000 × 27.000 | 15668.039 | 25²×27 − π·4.75²·12 − π·2.75²·15 = 15668.08(差 0.04mm³) |
| 1-09 エンドプレート | 48.000 × 48.000 × 6.000 | 10446.801 | φ48×6 − 2×φ6.6×6 = 10446.80(差 0.00) |
| 3-05 ベアリングカラー | 40.000 × 4.750 × 40.000 | 2274.513 | — |
| 1-25 走行LSドグ | 100.000 × 45.000 × 12.000 | 47196.372 | — |
| 1-12 リニアガイドカバー | 1015.000 × 50.000 × 3.200 | 161756.602 | — |

SW計測API(`ISurface.CylinderParams`)での円筒面直径も設計値ぴったり(3-05: φ40 / φ38 / **φ30.0000**)。
`swImportNeutralUnits(580)=0`(= ファイル指定単位)が既定で、STEPのmm指定がそのまま入る。

### 2-2. ❗材質は入らない → 重量の自動算出はSTEPからは不可能

`GetMaterialPropertyName2()` は全部品で `['', '']`、密度は **1000 kg/m³(水)** に落ちる。
表題欄の重量は **依頼JSONの材質 × SW体積** で出すしかない(`generate_drawing.resolve_density` の経路が正)。

### 2-3. ❗STEPの座標系は部品ごとにバラバラ

| 部品 | 部品の主軸/厚み方向 | SWの各ビューが見せる面 |
|---|---|---|
| 1-18 クッション | 穴軸 = **Z** (0→27) | front=25×25(円が見える) |
| 1-09 エンドプレート | 板厚 = **Z** (0→6) | front=48×48(円が見える) |
| 3-05 ベアリングカラー | 穴軸 = **Y** (0→4.75) | front=40×4.75(**厚みの縁**)/ top=40×40(円が見える) |
| 1-25 走行LSドグ | 板厚 = **Z** (0→12) | front=100×45(輪郭が見える) |
| 1-12 リニアガイドカバー | 板厚 = **Z** (0→3.2) | front=1015×50(輪郭が見える) |

**3-05 だけ主軸がYを向いている。** つまり「STEPのZ軸が板厚/主軸」という前提は置けない。
なお原点位置もバラバラ(1-25は `x:0..100` と原点が端、1-18は `x:-12.5..12.5` と中心)。

### 2-4. ❗STEPインポート品は円筒が2枚に割れており、投影に「継ぎ目の線」が出る

3-05 の円筒面は φ40・φ38・φ30 が**それぞれ2面ずつ**(計6面)存在した。
STEP由来のB-repは円筒を半割りで持っているため、その境界(接線エッジ)が
**図面ビューに余計な直線として描かれる**。1-18の右側面図では穴の中心線位置に
実在しない水平線が2本入り、人間図面との一致率が 1.000 → 0.872 に落ちた。

**対策(実証済み)**: `SetDisplayTangentEdges2(0)`(= swTangentEdgesHidden)にすると
継ぎ目線が消え、**一致率が 1.000 に戻る**。
※ CLAUDE.md の「接線エッジは `SetDisplayTangentEdges2(1)` 一択」は
**SW native モデル前提の知見**であり、STEP入力では逆になる。フィレットの接線エッジも
同時に消えるため、フィレットのある部品では別途の対処(継ぎ目線だけを除去する後処理)が要る。

## 3. 部品ごとの照合結果

### 3-1. 照合方法

1. 人間図面から `subtract_frame()` で図枠を差し引く(非バケットAは差し引かず幾何のみで比較)
2. **風船(部品番号の丸)を除去**(円の中に `NN-N` 形式の文字があるものを風船と判定)
3. 残りを空間クラスタリングしてビュー候補にし、第三角法の配置から役割(正面/平面/右側面)を推定
4. 尺度セルと用紙倍率から **DXF1単位 → 実物mm** を換算
5. SWの各ビューに **8通りの平面変換(回転4 × 鏡像4)** を掛けて、
   0.4mm格子の相互被覆率が最大になる変換を機械探索する(**行列式-1=鏡像も必ず候補に含める**)

指標: `一致` = min(SW側被覆, 人間側被覆)。`外形差` = 幅・高さの最大差。

### 3-2. 結果表(接線エッジ非表示 `SetDisplayTangentEdges2(0)` での値)

| 図番 / 品名 | 図枠 | 尺度 / 用紙倍率 | 人間ビュー | ← SWビュー | 変換 | det | 一致 | 外形差 | 円 直径 (SW / 人間) | 判定 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1-18 クッション | A(112/113除去) | 1:1 / ×1 | front 25×25 | front | **恒等** | +1 | **1.0000** | 0.000mm | 5.5, 9.5 / 5.5, 9.5 | **一致** |
| 〃 | | | right 27×25 | right | **恒等** | +1 | **1.0000** | 0.000mm | — | **一致** |
| 1-09 エンドプレート | A(113/113) | 1:1 / ×1 | front 48×48 | front | **恒等** | +1 | **1.0000** | 0.009mm | 6.6, 6.6, 48.0 / 6.6, 6.6, 48.0 | **一致** |
| 〃 | | | top 48×6 | right | 回転90 | +1 | 0.9195 | 0.000mm | — | 一致(人間が隠れ線を省略) |
| 3-05 ベアリングカラー | A(113/113) | 1:1 / ×1 | front 4.75×40 | **front** | **回転270** | +1 | **1.0000** | 0.000mm | — | **要回転(紙面90°)** |
| 〃 | | | right 40×40 | **top** | 回転90 | +1 | **1.0000** | 0.009mm | 30.0, 38.0, 40.0 / **30.1**, 38.0, 40.0 | **要回転 + 人間図面の作図誤差** |

| 1-12 リニアガイドカバー | 非A(差引無) | **1:3 / ×3** | front 1015×50 | front | **恒等** | +1 | **1.0000** | 0.000mm | 8.0×4 / 8.0×4 | **一致** |

「同点変換の数」= 形状の対称性によって区別できない変換の個数:
1-18 front=8(完全対称)/ 1-09 front=4 / 3-05 front=2 / **1-25 front=1(唯一解)** / 1-12 front=2。

### 3-3. 鏡像(行列式-1)の判定

- 5部品すべてで**最良変換の det = +1**。鏡像が必要な部品は無い。
- ただし対称部品では鏡像と回転が同点になり原理的に区別できない
  (1-18は8変換すべて同点=判定不能)。**非対称部品でしか鏡像は検出できない**という
  姉妹プロジェクトの教訓どおりの結果になった。
- **1-25 走行LSドグ**は左下に45°の面取りがあり左右非対称・上下非対称のため、
  8変換のうち**恒等ただ1つ**が一致した(他7つは一致0.12〜0.30)。
  → **STEPは鏡像化していない**ことをこの1点で確定できる。

### 3-4. 一致しなかった項目の切り分け(0.5mm超は無かったが、0.1mmの差を1件検出)

**3-05 ベアリングカラー: 人間図面の内径が φ30.1 で描かれている**

| 情報源 | 値 |
|---|---|
| 人間図面の CIRCLE 実体 | **φ30.1**(半径15.05) |
| 人間図面の寸法文字 | `%%c30 +0.05/0`(= φ30 公差+0.05/0) |
| 人間図面の寸法defpoint間距離 | 30.0000 |
| **3Dモデル実測(SW `CylinderParams`)** | **φ30.0000**(2面とも) |

→ **STEPが正しく、人間図面の作図が0.1mmずれている**。
CLAUDE.md の「人間の参考図面はジオメトリの正解ではない」の**3例目**
(1例目=ホルダーの2-8キリがφ7で作図、2例目=端子棒φ25の測定点)。

**1-09 エンドプレート top / 1-18 right: SW側の被覆が0.85〜0.92**

不足しているのは全て**SW側にだけある隠れ線**。
- 1-09の板厚ビュー: SWはφ6.6穴の隠れ線を描くが、**人間は描いていない**(作図流儀)
- 1-18の右側面: 接線エッジ表示ONのときに出る継ぎ目線(§2-4)。OFFで解消
→ どちらも**ジオメトリの不一致ではない**。人間側被覆は常に 1.0000(=人間が描いた線は
すべてSW側に存在する)。

## 4. 「STEPの向きは人間の正面と一致するか」の結論

**答え: 投影像は完全一致するが、向きの選び方は一致しない。**

1. **形は完全に一致する**。5部品すべてで、適切なビュー方向を選べば
   **一致1.0000 / 外形差0.000mm / 円の直径集合も完全一致**。歪み・スケール誤り・鏡像は無い。
2. **「正面」の軸は一致するとは限らない**。
   4/5部品では人間の正面 = SWの正面(モデルXY面)だったが、
   **3-05 ベアリングカラーでは人間の正面 = SWの正面を紙面上で270°回した図**であり、
   さらに人間の右側面図 = **SWの平面図**だった(主軸がYを向いているため)。
3. したがって **「STEPの座標系をそのままビュー割りに使う」設計は不可**。
   ただし補正に必要なのは**90°単位の回転と軸の入れ替えだけ**で、鏡像も微小回転も不要。

## 7. フェーズ4(量産検証)への申し送り

### 7-1. 必須: 「正面ビュー選定」機構(向き補正)

STEPの座標系は使えないので、**形状から正面を決める**必要がある。実測データから、
以下の決定論的ルールで今回の5部品は全て正しく選べる:

1. **主軸(回転軸)の検出**: 円筒面群の軸ベクトルを集計し、最頻の軸をモデル主軸とする
   (`ISurface.CylinderParams` の `axis`。3-05 は全6面が `(0,-1,0)` → 主軸=Y)
2. **旋盤物(円筒面の総面積比が大きい)**: 主軸を**紙面水平**に置く。
   → 正面 = 主軸に垂直な方向から見た図(輪郭図)、右側面 = 主軸方向から見た図(円が見える図)
   → 3-05 の人間図面(front=4.75×40の輪郭 / right=φ40の円)とこのルールが一致
3. **板物(平面が支配的・厚みが他2辺より十分小さい)**: 板厚方向を**紙面法線**に置く。
   → 正面 = 板の広い面(1-09/1-25/1-12/1-18 はこれで人間図面と一致)
4. 決めた向きは **90°単位の回転(24方位)のみ**で表現できる。鏡像は不要と実証済み

実装の置き場所: 作図計画(フェーズ3)の入口。`draw_pipeline.insert_standard_views` に
「モデル→ビューの回転」を渡せるようにする(SWのビュー方向指定または
`IView.Angle` の90°単位設定)。**照合ツール(`compare_views.py`)はそのまま
「向き補正が正しかったか」の検証ゲートに転用できる**。

### 7-2. 必須: 接線エッジモードの扱い

- STEP入力では **`SetDisplayTangentEdges2(0)` を既定にする**(円筒の継ぎ目線が消える)
- ただしフィレットの接線エッジも消えるので、フィレットのある部品では
  「継ぎ目線だけ除去」が要る。判定材料: 継ぎ目線は**両側の面が同一半径・同一軸の円筒**。
  当面はフェーズ4で「接線エッジON/OFF両方を出して人間図面と一致した方を採用」でよい
  (今回の照合ツールがそのまま使える)

### 7-3. 必須: 重量は依頼JSONの材質から

STEPは材質を持たない(密度が水1000kg/m³に落ちる)。
表題欄の重量は `resolve_density(材質) × SW体積` で計算すること。**SWの Mass をそのまま使うと全部間違う**。

### 7-4. 照合の自動化に必要だった前処理(全部ハマった)

1. **図枠のレイヤ名は当てにならない** → `subtract_frame(ignore_layer=True)`(修正済み)
2. **風船(部品番号の丸)を部品の穴と誤認する** → 径は図面ごとに違う(φ10/φ16)し
   **部品の輪郭の内側にも置かれる**。「円の中に `NN-N` の文字があるか」で判定する
3. **表面性状記号(▽)がビューにくっつく** → 単一のクラスタギャップでは分離できない。
   複数ギャップ(8/4/2mm)で候補を作って照合スコアで選ばせる
4. **ポリラインのbulge(円弧)を無視すると外形が壊れる** → 1-18の円形ビューの外形は
   「2頂点+bulge」のLWPOLYLINEだった。LINE/ARCへ展開してから測る
5. **尺度と用紙倍率は別物** → `DXF1単位 = (尺度分母/分子) / 用紙倍率` [mm]。
   1-12は 用紙倍率3 × 尺度1:3 で偶然1.0になる。**片方だけ見ると倍率3倍の事故になる**

### 7-5. 検証ゲート④(人間図面比較)の合格基準の提案

今回の実測を踏まえた提案:

| 指標 | 合格基準 | 根拠 |
|---|---|---|
| 円の直径集合 | 一致(許容 0.05mm) | 実測差は 3-05 の0.1mm 1件のみ。それは人間図面の誤り |
| ビュー外形 | 差 ≤ 0.05mm | 実測 0.000〜0.009mm(0.009は円弧のサンプリング誤差) |
| 人間側被覆 | **1.0000 必須**(人間が描いた線は全てSW側に在ること) | 実測全件 1.0000 |
| SW側被覆 | 0.85以上で警告どまり(隠れ線の作図流儀差を許容) | 人間は板厚ビューの隠れ線を省略する |
| 変換 | det=+1 かつ 90°単位 | 鏡像が最良になったら**即停止**(モデルかSTEP変換の事故) |
