# ゲート④(人間図面との比較)への「様式スコア」追加提案

作成日: 2026-08-10 / 担当: Executor(サブエージェント・図面様式分析)

> 前提: `CLAUDE.md`のゲート④は現状「自社流儀の再現度を採点」する枠のみで、
> 具体的な機械測定指標が定義されていない。ゲート①②③は「正しさ」(値・完全性・目視の破綻なし)
> を保証するが、**「正しいが機械的で読みにくい」図面はどれも通過してしまう**
> (`調査/drawing_style_analysis.md`で実測)。以下は同レポートの定量結果を根拠にした、
> **機械測定可能な様式スコア案**。ゲート①②③を置き換えるものではなく、
> ゲート④(合否ではなく参考スコア・トレンド監視用)に追加する提案。

---

## 1. 設計方針

- **ブロッキングゲートにはしない**: 様式は「好み」の要素を含み、1部品単位で外れ値が出ても
  即不合格にすべきではない。ゲート①②③(正確性)とは独立に**参考スコア(0〜100)を記録し、
  台帳・盲検レポートでトレンド監視**する運用を推奨。
- **全て生成DXFの実エンティティから機械測定できる**(計画JSONの自己申告に依存しない。
  CLAUDE.md「自己申告を信用しない」原則を踏襲)。
- **基準値は`調査/drawing_style_analysis.md`の人間コーパス実測(バケットA・15枚)から取る**。

---

## 2. 指標案

### 2.1 直径・半径の左右バランス指数(Diameter Side Balance)

**測定**: 各ビューで、直径+半径寸法の `text_midpoint` がビューbbox中心に対し
left/right どちらかを`調査/style_pattern_analysis.py`の`classify_side`と同じ方法で判定。
`balance = min(left_n, right_n) / max(left_n, right_n)`(径寸法が2本未満のビューは対象外)。

**基準値**: 人間コーパス実測は直径 left42%:right53%(ほぼ1:1)。`balance`の目安は
**0.5以上**(2:1以内の偏りまで許容)。生成5枚の実測(pooled)は left75%:right12%で
`balance≈0.16`相当。

**スコア化**: `score = min(1.0, balance / 0.5) × 100`

### 2.2 径帯・長さ帯の分離指数(Kind-Side Separation)

**測定**: 直径寸法が最も多いside(例: left)に対し、その同じsideに置かれた長さ寸法の比率
`overlap = length_on_dominant_diameter_side / length_total`。

**基準値**: 人間コーパスは「径の帯」(left)に長さが乗る比率12%。**20%以下を目安**。
生成5枚pooledは34%(基準の約3倍)。

**スコア化**: `score = max(0, 100 - (overlap - 0.12) / 0.20 × 100)`
(overlap=0.12で100点、overlap=0.32で0点になるよう線形)

### 2.3 直列連記(chain)使用率

**測定**: `調査/style_pattern_analysis.py`の`analyze_chaining`と同じロジック
(同一方向・同一寸法線レベル・端点が接する寸法の組)で、
`chain_ratio = chained_dims / (chained_dims + baseline_dims + isolated_dims)`。

**基準値**: 人間コーパス実測は水平23%・垂直17%(平均20%)。生成5枚は0%。
**目安は10%以上**(人間の下限に近い値。0%は「直列連記という選択肢が計画に存在しない」
ことを示す構造的シグナルとして扱う)。

**スコア化**: `score = min(1.0, chain_ratio / 0.20) × 100`

### 2.4 密度スコア(1ビューあたり寸法本数)

**測定**: ビューごとの寸法本数(実ビュー数は`layout.views`計画値または投影ビュー数を使う。
本分析の空間クラスタリングは近接ビューを誤融合するため**採用しない**、§0.3参照)。

**基準値**: 人間コーパス中央値4本・平均4.8本・90パーセンタイル約8本。
**8本を超えたら要注意フラグ**(即減点ではなく警告)。

**スコア化**: `score = 100 if per_view_count <= 6 else max(0, 100 - (per_view_count - 6) × 15)`
(6本までは満点、6本超から緩やかに減点、12本で0点)

### 2.5 角度寸法・PCD位相の整合(Phase Coverage)

**測定**: PCD注記(`find_pcd_groups`のヒット)が存在するビューについて、
そのビュー内に角度寸法(dimtype=2)が1本以上あるか、またはPCD円上の1穴が
他の基準寸法(直線寸法)で位置固定されているかを確認する。

**基準値**: 定性指標(人間実例3-02はPCD2件に対し角度寸法3本を併用)。
**「PCD注記がある図面で位相を示す寸法(角度またはそれに準じる位置寸法)が0件」を検出**する
チェックリスト的スコア(0/1のフラグに近い)。

**スコア化**: `score = 100 if phase_dim_present else 60`
(位相欠如は即不合格ではないが減点。ゲート②が位相を判定対象外にしていることの補完)

### 2.6 中心線の有無(Centerline Presence)

**測定**: 円・円弧を含むビューにDASHDOT線種のLINE(対称中心線)が存在するか、
PCD穴群を含むビューにDASHDOT CIRCLE(ピッチ円中心線)が存在するか。

**基準値**: `調査/dimension_style_analysis.md`§5.2実測 — 対称中心線はほぼ全部品(既存流儀で
実装済みのはず)、PCD中心線はPCDを持つ部品の80枚中16枚(20%。PCD穴群がある部品では
ほぼ必須の描画要素と解釈すべき=PCD穴群を持つ部品では100%に近いことが期待値)。

**スコア化**: `score = 100 if all_expected_centerlines_present else 100 × present/expected`
(既存エンジンが対称中心線を出す前提なら基本満点になるはずで、**主にPCD中心線の欠落検出**に効く)

### 2.7 はめあい面の公差・仕上げ記号カバレッジ(Fit Surface Annotation)

**測定**: 3D実測データ(`meas.json`)の段付き円筒穴/軸のうち、径・深さが軸受規格
(JIS B 1512等の内外径レンジ)やオイルシール規格に近い(許容±0.5mm程度)候補について、
生成DXFの対応する直径寸法にdimtol(片側公差)または仕上げ記号(AGM_JISB0031)が
付いているかを機械チェック。

**基準値**: `調査/drawing_style_analysis.md`§3実測 — 3実例中3例で「公差と仕上げ記号は
常にペアで機能ばめ面にのみ付く」。**候補面のうち1つも公差/仕上げが付いていない生成図面は
要確認**(必ずしも不正解ではない。3Dからは相手部品情報が読めないため「検討した形跡」の有無を
見る指標)。

**スコア化**: `score = 100 if fit_candidates == 0 else 100 × annotated / fit_candidates`
(公差候補が無い部品は自動的に満点。**加工者観点で見落としを可視化する診断指標**として運用)

---

## 3. 総合様式スコア(提案)

```
style_score = 0.25×diameter_balance + 0.15×kind_side_separation + 0.20×chain_ratio_score
            + 0.15×density_score + 0.10×phase_coverage_score + 0.10×centerline_score
            + 0.05×fit_surface_score
```

重みは「本分析でギャップが大きかった指標(直径バランス・帯分離・直列連記)を重く」
という考え方で仮置き。ディレクター裁定で調整可能なようパラメータ化を推奨
(`図枠/style_score_spec.json`のような重み定義ファイルを別途切って、既存dimstyle_specと
同じ運用にするのが良い)。

## 4. 実装上の注意

- **本提案の指標自体は`調査/style_pattern_analysis.py`のロジックをほぼ流用できる**
  (side分類・chain判定は既に実装済み)。ゲート④への正式組み込みはengine/配下の変更を伴うため
  **本タスクのスコープ外**(ディレクター承認・別エージェントでの実装が必要)。
- 密度・位相の基準値(§2.4・2.5)は**バケットA15枚という小コーパス**からの推定であり、
  今後の盲検・修理パスで蓄積されるデータで再校正すべき(`調査/drawing_style_analysis.md`§0.3の
  限界と同じ注意が必要)。
- 2.7(はめあい面カバレッジ)は3Dから相手部品情報を読めない限界が明確なため、
  「不合格」ではなく「要確認フラグ+解釈レポートへの記載を促す」運用が適切
  (CLAUDE.mdの「材質・個数は依頼JSON必須入力、AIに推定させない」方針と整合)。
