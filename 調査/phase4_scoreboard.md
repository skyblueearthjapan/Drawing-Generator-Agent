### 2-2. なぜ対照が強いのか(教師データの性質)

人間が実際に選んでいた紙面法線・紙面水平をモデル座標系へ逆算した結果(`調査/phase4_batch/analyze_orientation.py`):

| 人間の紙面法線 | 件数 | 人間の紙面水平 | 件数 |
|---|---|---|---|
| **モデル ±Z** | **17 / 25 (68%)** | **モデル +X** | **15 / 25 (60%)** |
| モデル ±X | 6 | モデル −Z | 6 |
| モデル ±Y | 2 | モデル ±Y | 3 |

教師の3Dモデルは元々 SolidWorks で **「正面(XY)平面にスケッチしてZ方向へ押し出す」** 流儀で作られており、
SW2026→STEP変換はその座標系を保っている。したがって **STEPの座標系そのものが「人間の正面」の強い事前分布**になっている。
step_import_report.md §7-1 の「STEPの座標系は使えない」は、**5部品中1点(3-05)の反例に引きずられた過大な一般化**だった。

### 2-3. 外した14件の内訳(2種類しかない)

| 外し方 | 件数 | 部品 | 何が起きているか |
|---|---|---|---|
| **A. 紙面法線を取り違えた** | 9 | 1-28 / 2-11 / 2-13 / 2-14 / 4-14 / 4-15 / 5-13 / 7-04 / 7-05 | 下の A-1 / A-2 |
| **B. 法線は合っていて紙面内回転だけ外した** | 5 | 2-12 / 3-12 / 4-10 / 5-15 / 5-16 | 下の B-1 / B-2 |

**A-1. 曲げ物ブラケット・ドグで「最小辺=板厚」を紙面法線にすると外す(6件: 1-28/2-11/2-14/4-14/4-15/5-13)**
これらは板を曲げた/削り出した立体で、**板厚方向は人間の紙面法線ではない**。
人間が選んだ法線は 6件すべて bbox の**中間辺**(1件だけ最大辺)であり、しかもその軸は
9件中6件で**モデルのZ軸**だった。つまり「板厚を法線に」より「モデルZを法線に」の方が当たる。
例: 2-14 LSドグ(34×9×31)は板厚Y=9 を法線にしたが、人間は Z=31 を法線に選んでいた。

**A-2. 旋盤物で「主軸に直交するどちらから見るか」の選択(2件: 7-04 端子棒 / 7-05 ホルダー)**
**主軸を紙面水平にする判断自体は正しかった**(人間も主軸Zを紙面水平にしている)。
外したのは主軸に直交する2軸(X/Y)のどちらを紙面法線にするかで、v1は決め打ちで Y を採った。
人間は2件とも **法線=+X・紙面水平=−Z**、これは SWの **`*右側面` を回転0で使うのと完全に同一**。
7-05 は一致度 0.9992(ほぼ同じ絵)なので実害は小さいが、判定上は不正解。

**B-1. 紙面内180度(2件: 3-12 / 4-10)** — 法線も水平軸も正しく、向きの符号だけ逆。
**B-2. 紙面内90度(3件: 2-12 / 5-15 / 5-16)** — v1は「直交2辺のうち長い方を紙面水平」にしたが、
人間は短い方(いずれもモデルX)を水平にしていた。
なお唯一この規則で勝ったのが 4-08 開口部カバー(123×220×1.6 の大板で人間も長辺Yを水平)。
**「長辺を水平」は大きな平板でだけ成立し、立体ブラケットでは成立しない。**

**符号(±)を決める手掛かりの探索**: 「重心が寄っている側を紙面右に向ける」仮説を検定したが
**9件中3件しか当たらず棄却**(`重心偏り>2%` の部品のみで集計)。符号はbbox・重心からは決まらない。

## 4. ゲート④の合否と、落ちた理由の分解

### ❗ ゲート④合格基準案の見直しが要る(5部品では見えなかった)

step_import_report.md §7-5 の基準は5部品(すべて単純形状)で作られたもので、30部品では次の点が破綻した:

1. **「人間側被覆 1.0000 必須」は厳しすぎる** — ねじの簡略図示だけで7件が落ちる。
   → **ねじ表現円(呼び径円/谷径円)を照合前に除去**する前処理が必要。判定材料は
   「同心の2円で、外側:内側の径比が 0.8〜0.87(=JISのねじ谷径比)」。
2. **「円の直径集合の一致」も同じ理由でねじを除外してから測る**。
3. **鏡像(det=−1)の即停止も円照合も、ビュー対応が正しいことが確定してからでないと意味が無い**。
   実測: 鏡像フラグは v1(向きが4件外れている)で4件、対照(向きが合っている)では1件に減った。
   円の偽陽性も1件出た(4-15)。→ 判定順序を **向き一致 → 鏡像 → 幾何(外形・円)** に固定すべき。
4. SW側被覆の警告(0.85)は妥当。6件とも隠れ線の流儀差で説明がつく。

## 6. 新しい罠(このバッチで踏んだもの)

1. **❗`IView.Angle` は radian・正=反時計回り(CCW)**。`90` を代入すると 90rad=2.0354rad に折り返り、
   ビューが半端な角度になる(例外は出ない)。`ModelToViewTransform` は追随するので**代入後に読み戻して検証できる**。
   → `draw_pipeline._set_view_angle()` に検証つきで実装。**回転は `GetOutline` を測る前に入れる**(縦横が入れ替わるため)。
2. **❗`sys.stdout = io.TextIOWrapper(sys.stdout.buffer, ...)` をモジュール読み込み時に重ねてはいけない**。
   import する側が同じ包み方をしていると外側のラッパーが参照を失ってGCされ、
   その `__del__` が**共通のバッファを閉じる** → 以後の print が `ValueError: I/O operation on closed file`。
   `sys.stdout.reconfigure(encoding=...)` は冪等で安全。`compare_views.py` / `render_step_check.py` / バッチを修正済み。
3. **❗用紙倍率を「作図範囲の最大X幅 / 410」で推定してはいけない**(実害4件: 2-13/2-202/4-08/5-13)。
   図枠の外へ出る引出線などで幅が820を超え、倍率2と誤判定 → 尺度が半分になり
   **部品ビューが1つも同定できず「判定不能」**になっていた。

## 11. 測定器(照合ツール)の重大バグと、その修正

### 11-1. ❗非バケットA図面の用紙倍率推定が壊れていた(実害15件)

第2弾の初回集計は **30点中13点が「照合不能」**という異常な値だった。原因を追うと
**照合不能13点のうち11点がすべて非バケットA**で、しかも全件が「部品ビューを1つも同定できない」。

`compare_views.load_human()` は、図枠テンプレートが一致しない図面では
**用紙倍率を「作図範囲の最大X幅 / 410」で推定**していた。非バケットAは図枠が別バリアントなので
テンプレートが一致せず、この推定に落ちる。実測値は倍率 **2 / 3 / 4 / 18**(!)と出鱈目で、
さらに**尺度セルの探索アンカーもその外れた倍率でスケールされる**ので誤りが連鎖する。
結果 `sf`(DXF1単位→実物mm)が 1/2〜1/18 になり、人間図面のビューが実寸の数分の1と解釈され、
**SW投影の外形と1つも一致しなくなる**。

**修正**: `sf` は `(尺度分母/分子)/用紙倍率` なので**取り得る値は離散的**。
`sf` で部品ビューが0個だったときだけ、候補 `{1, 1/2, 2, 1/3, 3, 1/4, 4, 1/2.5, 2.5, 5}` を走査して
**部品ビューが最も多く同定できる `sf` を採る**(`compare_views.SF_CANDIDATES`)。
当てずっぽうではない: **モデル実測から作ったSWビュー外形3つとの一致で検算している**。
偽陽性(寸法文字の枠などが偶然一致する)を避けるため、部品ビューが8個を超える候補は捨てる
(`SF_MAX_PART_VIEWS`。実際 3-07 転造ボールネジで `sf=5` が52個を拾う偽陽性が出た)。

**効果**(60点を3条件とも `--recompare` でやり直した):

| | 修正前 | 修正後 |
|---|---|---|
| 照合不能(60点中) | 19点 | **10点** |
| うち第2弾 | 13点 | **4点** |
| 非バケットAで判定できた率 | 6/21 | **15/21** |

**救済された12点はすべて `sf=1`(用紙倍率1・尺度1:1)が正解**だった。
つまり **これらの図面は最初から等倍**であり、幅推定だけが間違っていた。

3条件すべて外した16点: 1-28 / 2-13 / 3-12 / 4-10 / 4-15 / 5-13 / 1-03 / 1-17 / 1-26 / 2-04 / 2-09 / 3-06 / 3-22 / 5-12 / 6-11 / 7-09。
**§12 の上位3候補(78%)の方が、3つのルールを回すより当たる。ルールを増やす方向は筋が悪い。**

## 13. ★向き選定戦略の最終推奨

### 13-1. 決定論ルールについて

1. **v1(形状主導)は破棄する。** 60点で 40.0%、対照に16ポイント負け、勝てる形状クラスが1つも無い。
2. **v2 は「採用しても害は無いが、得も無い」。** 独立検証で対照と完全に引き分け(53.8%)。
   狙った旋盤物でも 3/6 対 3/6。**「v2 で十分か」への答えは No**。
3. **既定の単一推定は「対照 = STEPの座標系そのまま(`*正面`・回転0)」で良い。**
   ルールを足さない分だけ壊れる余地が少なく、実測 56%(60点)/ 53.8%(第2弾)。
   `engine/view_orient.py` の `RULE_VERSION_DEFAULT` は**恒等(対照)相当に倒すのが妥当**
   (v1/v2 のコードは検証履歴として残す)。

### 13-2. 本番(人間図面が無い)でどうするか — 候補提示 + AIオペレータ選択

**これが本命の推奨。** §12 の「候補集合が24通りで閉じている」という構造的事実を使う。

1. **候補生成(決定論)**: SW標準6ビュー × 90度単位回転4通り = 最大24候補。
   **形状クラス別の事前分布(§12-1)で順位付け**し、上位 **N=6** を投影する。
   6候補で人間の選択を **90%** 被覆する(50点実測)。1候補あたり数秒なので追加コストは小さい。
2. **AIオペレータが選ぶ**: 各候補を `compose_drawing.render_png` でPNG化し、
   **「どの候補が部品の特徴(段付き・穴配置・曲げ)を最もよく見せているか」**をAIが判断して1つ選ぶ。
   これは既存アーキテクチャの「推論はAI」の層にちょうど乗る仕事であり、
   幾何ヒューリスティクスが2世代続けて失敗した領域そのものである。
3. **決定論のゲートは残す**: 選んだ候補について、ゲート①(寸法値照合)・ゲート②(寸法完全性)は従来どおり効く。
   **向きの選択が主観的でも、その後の検証は決定論のまま**なので品質保証は崩れない。
4. **人間への質問票**: 上位候補が拮抗する場合(特に旋盤物で `*正面`+0 と `*右側面`+0 が並ぶ場合)は、
   **PNGを2枚並べて人間に選ばせる**。「不明点は勝手に仮定して納品しない」という憲章の運用そのもの。

### 13-3. どの形状クラスで外れるか(= 候補提示を厚くすべき所)

| クラス | 単一推定(対照)の的中 | 対応 |
|---|---|---|
| plate / holed_block | 65〜67% | 上位3候補で 78〜100%。**N=3 で足りる** |
| other(曲げ物ブラケット・ドグ) | 50% | `*右側面`+0 と `*左側面`+0 が効く。**N=4 は要る** |
| **lathe** | **33%** | 順位を `*正面`+270 / `*右側面`+0 に入れ替える。**N=4〜6 が要る** |

**外れた部品を救う次の一手**(効果の大きい順):

1. **候補提示 + AI選択に切り替える**(§13-2)。単一推定 55% → 上位6候補 90%。効果が最も大きい。
2. **旋盤物の候補順位を入れ替える**(§12-1)。決定論のままでも lathe の top-1 を 33% から改善できる可能性。
   ただし**9点しか無いので、次バッチで旋盤物を20点以上集めてから決めること**(2世代連続の失敗の再発防止)。
3. **鏡像候補(`*左側面`/`*背面`/`*底面`)を必ず候補集合に入れる**。50点中2点(4%)が
   `*右側面` の鏡像 = `*左側面` を正面にしていた。片側3方向だけでは原理的に届かない。

## 14. 第2弾で踏んだ新しい罠

1. **❗用紙倍率を作図範囲の幅から推定してはいけない(第1弾 §6-3 の完全版)**。

2. **❗荏原の品名は半角カタカナ混じり**(`ﾗｯｸ3-2000` `ｶﾊﾞｰ`)。
