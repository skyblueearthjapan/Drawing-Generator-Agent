### 2-3. 外した14件の内訳(2種類しかない)

| 外し方 | 件数 | 部品 | 何が起きているか |
|---|---|---|---|
| **A. 紙面法線を取り違えた** | 9 | 1-28 / 2-11 / 2-13 / 2-14 / 4-14 / 4-15 / 5-13 / 7-04 / 7-05 | 下の A-1 / A-2 |
| **B. 法線は合っていて紙面内回転だけ外した** | 5 | 2-12 / 3-12 / 4-10 / 5-15 / 5-16 | 下の B-1 / B-2 |

**A-1. 曲げ物ブラケット・ドグで「最小辺=板厚」を紙面法線にすると外す(6件: 1-28/2-11/2-14/4-14/4-15/5-13)**
これらは板を曲げた/削り出した立体で、**板厚方向は人間の紙面法線ではない**。
人間が選んだ法線は 6件すべて bbox の**中間辺**(1件だけ最大辺)であり、しかもその軸は
9件中6件で**モデルのZ軸**だった。つまり「板厚を法線に」より「モデルZを法線に」の方が当たる。
例: 2-14 LSドグ(34×9×31)は板厚Y=9 を法線にしたが、人間は Z=31 を法線に選んでいた。

**A-2. 旋盤物で「主軸に直交するどちらから見るか」の選択(2件: 7-04 端子棒 / 7-05 ホルダー)**
**主軸を紙面水平にする判断自体は正しかった**(人間も主軸Zを紙面水平にしている)。
外したのは主軸に直交する2軸(X/Y)のどちらを紙面法線にするかで、v1は決め打ちで Y を採った。
人間は2件とも **法線=+X・紙面水平=−Z**、これは SWの **`*右側面` を回転0で使うのと完全に同一**。
7-05 は一致度 0.9992(ほぼ同じ絵)なので実害は小さいが、判定上は不正解。

**B-1. 紙面内180度(2件: 3-12 / 4-10)** — 法線も水平軸も正しく、向きの符号だけ逆。
**B-2. 紙面内90度(3件: 2-12 / 5-15 / 5-16)** — v1は「直交2辺のうち長い方を紙面水平」にしたが、
人間は短い方(いずれもモデルX)を水平にしていた。
なお唯一この規則で勝ったのが 4-08 開口部カバー(123×220×1.6 の大板で人間も長辺Yを水平)。
**「長辺を水平」は大きな平板でだけ成立し、立体ブラケットでは成立しない。**

**符号(±)を決める手掛かりの探索**: 「重心が寄っている側を紙面右に向ける」仮説を検定したが
**9件中3件しか当たらず棄却**(`重心偏り>2%` の部品のみで集計)。符号はbbox・重心からは決まらない。

## 4. ゲート④の合否と、落ちた理由の分解

合格 7/30。**外形差・円直径差という「幾何そのもの」で落ちたのは2件だけ**(3-05 の既知の0.1mm と 2-12 の0.2mm)。

| 円直径差 > 0.05mm | 1 | 3-05 の φ30.1(既知の人間図面作図誤差) |

### ❗ ゲート④合格基準案の見直しが要る(5部品では見えなかった)

step_import_report.md §7-5 の基準は5部品(すべて単純形状)で作られたもので、30部品では次の点が破綻した:

1. **「人間側被覆 1.0000 必須」は厳しすぎる** — ねじの簡略図示だけで7件が落ちる。
   → **ねじ表現円(呼び径円/谷径円)を照合前に除去**する前処理が必要。判定材料は
   「同心の2円で、外側:内側の径比が 0.8〜0.87(=JISのねじ谷径比)」。
2. **「円の直径集合の一致」も同じ理由でねじを除外してから測る**。
3. **鏡像(det=−1)の即停止も円照合も、ビュー対応が正しいことが確定してからでないと意味が無い**。
   実測: 鏡像フラグは v1(向きが4件外れている)で4件、対照(向きが合っている)では1件に減った。
   円の偽陽性も1件出た(4-15)。→ 判定順序を **向き一致 → 鏡像 → 幾何(外形・円)** に固定すべき。
4. SW側被覆の警告(0.85)は妥当。6件とも隠れ線の流儀差で説明がつく。

## 6. 新しい罠(このバッチで踏んだもの)

1. **❗`IView.Angle` は radian・正=反時計回り(CCW)**。`90` を代入すると 90rad=2.0354rad に折り返り、
   ビューが半端な角度になる(例外は出ない)。`ModelToViewTransform` は追随するので**代入後に読み戻して検証できる**。
   → `draw_pipeline._set_view_angle()` に検証つきで実装。**回転は `GetOutline` を測る前に入れる**(縦横が入れ替わるため)。
2. **❗`sys.stdout = io.TextIOWrapper(sys.stdout.buffer, ...)` をモジュール読み込み時に重ねてはいけない**。
   import する側が同じ包み方をしていると外側のラッパーが参照を失ってGCされ、
   その `__del__` が**共通のバッファを閉じる** → 以後の print が `ValueError: I/O operation on closed file`。
   `sys.stdout.reconfigure(encoding=...)` は冪等で安全。`compare_views.py` / `render_step_check.py` / バッチを修正済み。
3. **❗用紙倍率を「作図範囲の最大X幅 / 410」で推定してはいけない**(実害4件: 2-13/2-202/4-08/5-13)。
   図枠の外へ出る引出線などで幅が820を超え、倍率2と誤判定 → 尺度が半分になり
   **部品ビューが1つも同定できず「判定不能」**になっていた。
   → **図枠テンプレートが100/113以上一致した時点で倍率1で確定**させる(`compare_views.FRAME_MATCH_MIN`)。
4. **❗「左下のビューが正面図」という規則は外れる**(実害: 4-15 指針ほか)。
   **左側面図があると最も左下に来るのは左側面図**であり正面図ではない。
   これを取り違えると**向きルールの正誤判定そのものが誤る=測定器が壊れる**。
   → 第三角法の構造整合(上下に並ぶ隣は幅を共有/左右に並ぶ隣は高さを共有)をスコアにして
   正面を決める `compare_views.assign_roles()` に置き換え。修正で判定不能が8件→5件に減った。
5. **人間図面のねじは3Dモデルに無い円を持ち込む**(M5→φ4.134、M4→φ3.242)。
   ゲート④の円照合はねじ表現を除去してからでないと機能しない(不合格9件の主因)。
6. **STEPインポートは1部品あたり7〜19秒**(投影4ビュー+DXF出力+照合込み)。
   30点で約5分。**SolidWorksのクラッシュは1度も起きなかった**(読み取り専用・QuitDoc運用)。

## 7. 次のバッチ(残り98部品)への改善提案

### 7-1. 最優先: ルールを v2 に差し替えて再測定する(実装済み・未検証)

`engine/view_orient.presentation_frame_v2()` として実装済み。`run_batch.py --rule=v2` で走る
(結果は `調査/phase4_batch/_v2/` に出るので v1 と併存できる)。

1. **既定 = モデル座標系をそのまま**(SWの`*正面`・回転0)
2. **旋盤物だけ上書き**して主軸を紙面水平にする
   - 主軸X → 恒等 / 主軸Y → `*正面`+270度 / **主軸Z → `*右側面`+回転0**
   (主軸Zの割り当ては 7-04/7-05 で人間の選択と完全一致することを実測から逆算した)

この30点での期待値は **18/25 = 72%** だが、**同じデータから作った仮説なので必ず別の部品で検証すること**。
まず残り98部品のうち30点で v1/v2/対照 の3条件を回し、v2 が対照に有意に勝つことを確認してから採用する。

### 7-2. 照合ツール側(測定器)の改善 — これをやらないと正解率の数字が信用できない

| 項目 | 内容 |
|---|---|
| **ねじ表現円の除去** | 同心2円で径比 0.80〜0.87 なら内側をねじ谷径として除去。9件の不合格が消える見込み |
| **照合対象外の自動判定** | ギア・ねじ部品(同軸径が4種以上/歯形らしい周期パターン)は幾何照合を諦め、別ゲートへ回す |
| **判定順序の固定** | 向き一致 → 鏡像(det) → 幾何。向きが外れている状態の det は無意味 |
| **役割推定の検算** | `assign_roles` のスコアが低い(構造整合が取れない)図面は「役割不明」として正解率の分母から外す |
| **非バケットAの図枠** | 6件中4件で図枠を引けず、尺度セルも読めない。バリアント図枠のテンプレート化が要る |

### 7-3. 対象選定

- **ギア/ねじ/歯付き部品を先に洗い出して別枠**にする(今回30点中5点=17%が照合不能だった)。
  棚卸しの品名に「ギア」「ネジ」「スプライン」を含むものは事前に分ける
- 曲げ物ブラケット・ドグ類が最大の外し要因なので、**次バッチではこのクラスを厚めに取る**
  (v2 が本当にこのクラスで効くかが勝負どころ)

### 7-4. 運用

- **チャンク6点/回で約1分**。10分上限に対して十分余裕がある。8〜10点/回まで上げてよい
- 再開は `result.json` の有無で自動判定。`--recompare` で**投影をやり直さずに照合だけ作り直せる**
  (照合ロジックを直したときに30点を数十秒で再評価できる。今回3回使った)
