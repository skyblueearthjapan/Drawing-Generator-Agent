# 中心線の流儀 — 人間図面144枚の機械採取(2026-08-10)

> 目的: ユーザー最重要フィードバック「**生成図面には中心線が無く図面として見にくい**」に対し、
> 荏原25154の人間図面から**中心線の流儀を測って**自動生成エンジンの既定値を決める。
> 採取スクリプト: `調査/analyze_centerline_style.py`(読み取り専用。荏原フォルダへは一切書かない)
> 生データ: `調査/centerline_style_stats.json` / 実行ログ: `調査/centerline/style_stats_log.txt`

## 0. 母集団と前処理

| 項目 | 値 |
|---|---|
| 走査した部品図DXF | 201枚のうち**組立図を除く**もの |
| 解析成立 | **144枚**(図枠外形から用紙倍率を確定できたもの) |
| 解析不能 | 13枚(A3図枠外形が無い大物/ラック/ギヤ図。用紙倍率が確定できない) |
| 用紙倍率の分布 | **1.0×83枚** / 1.5×21 / 2.0×16 / 3.0×15 / 4.0×8 / 2.5×1 |
| 中心線を1本も持たない図面 | **1 / 144** |

前処理で効いた3点(これを入れないと統計が壊れる):

- **図枠を先に落とす**。図枠込みでクラスタリングすると全部が1クラスタに融合し、
  「ビューを貫く軸」と「短い中心線」の区別が消える(初回実測で `over` の最大値が304mmに化けた)。
- **クラスタのギャップ幅は用紙倍率でスケールする**(`gap = 8mm × 用紙倍率`)。
- **同心円(穴+ザグリ)は1つの円形フィーチャーとして数える**。円単位で数えると同じ中心を
  二重計上して被覆率が歪む(実測: 1386→883件へ正規化)。

## 1. 線種・色・レイヤ — ここは完全に決まっている

| 項目 | 実測 | 採用 |
|---|---|---|
| 線種 | **DASHDOT 2290 / 2290 = 100%** | `DASHDOT` |
| 色 | **3(緑) 2257 / 2290 = 98.6%**(残りは7/1/4/6/5/11 が数本ずつ) | `3` |
| レイヤ | `3`(1387)・`1`(560)・`LEVEL003`(123)・`255`(64)・`LEVEL001`(58)・`0`(51)… | **意味なし** |

- レイヤ名はファイルローカルで統一されていない(CLAUDE.md「ブロック名/スタイル名/レイヤ名は
  いずれもファイルローカル」の3例目)。**生成側はレイヤ `0` に置き、線種と色で表現する。**
- ❗**DIVIDE(二点鎖線)は中心線ではない**。全体では DASHDOT より多く出るが(20枚で7328件)、
  中心線として使っている図面は無く、想像線・特殊指示に使われている。中心線の統計から外した。
- ❗**`図枠/frame_template.dxf` には DASHDOT が人間図面と同一パターンで既に定義済み**
  (`total=1.0 / dash .5 / gap -.25 / dot 0 / gap -.25`)。生成DXFの `$LTSCALE=8.4` は
  人間図面(用紙倍率1.5)の `$LTSCALE=12.6 = 8.4×1.5` と一致する = **見た目のピッチが同じになる**。
  線種を新規作成する必要は無い。

## 2. (a) 穴ごとのクロス中心線 — 円の外への延長量

**我々の出力は用紙倍率1・A3実寸なので、`用紙倍率1` の83枚が直接の目標値。**

| 用紙倍率 | n | p25 | **中央値** | p75 | 最頻値 |
|---|---|---|---|---|---|
| **1.0** | 168 | 4.50 | **5.00** | 7.00 | **5.0(64件=38%)** |
| 1.5 | 100 | 3.33 | 3.33 | 5.00 | 3.3 |
| 2.0 | 220 | 5.00 | 5.00 | 5.00 | 5.0 |
| 3.0 | 396 | 1.47 | 3.33 | 3.33 | 3.3 |
| 4.0 | 140 | 1.25 | 2.27 | 2.50 | 2.5 |

- 紙面mmでは全体 中央値3.33 / p75 5.00。**紙の上では 2.5〜5mm に収まる**。
- 作図空間(DXF単位)で見ると **10.0 が最頻(506/1024=49%)**、次いで 5.0(156)。
  用紙倍率2〜4の図面はほぼ「作図空間で10mm」= 紙面 5.0 / 3.3 / 2.5mm になっており、
  上表の倍率別の値はこれで説明が付く。
- **円の大きさへの依存はほとんど無い**(作図空間の中央値は D<6 / 6-12 / 12-25 のどのバケットでも 10.0)。
  比で見ると `延長/半径` は中央値1.67・p75 2.50 と大きくばらつく = **比ではなく絶対量の流儀**。

> **採用: `hole_ext_mm = 5.0`**(用紙倍率1の中央値かつ最頻値)。
> 第1段の寸法線オフセットは輪郭から16mmなので、5mmでは寸法と干渉しない。

## 3. (b)(d) ビュー全体を貫く軸中心線 — 輪郭からのはみ出し量

| 用紙倍率 | n | p25 | **中央値** | p75 | 最頻値 |
|---|---|---|---|---|---|
| **1.0** | 374 | 3.33 | **4.56** | 7.67 | 10.0(66) / 5.0(32) / 4.0(30) |
| 全体 | 658 | 2.02 | 4.24 | 6.58 | — |
| うち円形ビュー | 440 | 1.81 | 4.24 | 6.67 | — |
| うち輪郭/断面ビュー | 218 | 2.88 | 4.56 | 6.53 | — |

- **円形ビュー((b))と輪郭・断面ビュー((d)=旋盤物の軸中心線)で値が変わらない**
  → 分類を分ける必要が無く、1つのパラメータで足りる。
- 向きは 水平177 / 垂直152 でほぼ半々。
- 負値(輪郭の内側で止まる)も1割ほどある = 厳密な規則ではなく作図者の裁量。

> **採用: `axis_ext_mm = 5.0`**(用紙倍率1の中央値4.56に最も近い実在の丸め値。p25〜p75の内側)。

## 4. (c) PCD参照円

| 項目 | 実測 |
|---|---|
| 出現数 | 59件 / 144枚 |
| 実ジオメトリ検算(穴3個以上がその円に載る)が成立 | 50 / 59 |
| エンティティ型 | CIRCLE 58 / ARC 1 |
| PCD径 | 中央値73.3mm(p25 46.7 / p75 108.0 / 最大137.3) |

- **❗幾何だけで「同心・等距離の穴が3個以上」を条件にすると偽陽性が出る**(実装で実害):
  `25154-1-27 走行フレーム踏板`(長方形配置の6穴)は四隅の4穴が中心から等距離なので、
  板全体を覆う巨大な偽PCD円が描かれた。人間図面にPCD円は無い。
  正方形配置の四隅は「等距離かつ90度等分」まで満たすので、角度検査でも落ちない。
- **人間の流儀は「図面が ＰＣＤ と書いているときにその参照円を描く」**。
  → 実装は**穴注記の`ＰＣＤ<値>`を根拠にし、`gate2_completeness.find_pcd_groups` と同じ3点検算**
  (個数一致 / 中心円径がPCD値と一致 / 円周等分)を実ジオメトリで通ったものだけ描く。
  これで 1-27・4-05(いずれも人間もPCD円なし)は描かれず、3-02(2本)・5-05(1本)は人間と一致した。

## 5. (e) 輪郭ビューの穴軸マーク

円が見えないビュー(側面・断面)に現れる短い中心線。長さは 中央値17.5mm(p25 9.4 / p75 27.1)。
**穴の隠れ線(壁)の範囲に延長量を足した長さ**になっている。

> **採用**: 対応する穴の壁(軸から±rにある軸平行線分)の範囲を実ジオメトリから求め、
> 両端に `mark_ext_mm = 5.0` を足す。**壁が見つからないときは描かない**(でっち上げない)。

## 6. 「一直線に並ぶ穴は1本でつなぐ」

`25154-1-27` の実測: 3個並んだ穴の列は**板を横断する1本の一点鎖線**で描かれており、
穴ごとの短い十字ではない。穴ごとに切ると見た目が細切れになり、
元の指摘(「図面として見にくい」)に逆戻りする。

> **採用**: 同一ビュー・同一方向・同一位置の穴クロスは1本へ統合し、
> `[最初の穴の端 − ext, 最後の穴の端 + ext]` を張る。
> 実測効果: 4-05 の中心線 53本 → 36本、1-27 は 18本 → 11本で人間図面の見た目に一致した。

## 7. 円形フィーチャーへの被覆率(ゲート③の基準づくり)

同心円を1件に正規化した883件について「中心を通る中心線があるか」:

| 円径(モデルmm) | n | 中心線あり | 縦横両方 |
|---|---|---|---|
| d<3 | 180 | 76.7% | 69.4% |
| 3–6 | 314 | 70.7% | 60.5% |
| 6–12 | 232 | 68.5% | 51.3% |
| 12–25 | 104 | 20.2% | 20.2% |
| 25–60 | 16 | **100%** | **100%** |
| d≥60 | 37 | **100%** | **100%** |
| **合計** | **883** | **67.2%** | **57.5%** |

- **φ25以上の円は例外なく100%中心線が付く**。小径穴は7割前後で、作図者の裁量に幅がある
  (12–25mmが低いのは、ねじ表現円や座ぐりの中間径など「主フィーチャーでない円」を
   こちらが円として数えているため。人間はそれらに個別の中心線を引かない)。
- **生成側の方針**: 人間の67%に合わせるのではなく**全ての円形フィーチャーに縦横の中心線を付ける**
  (超集合)。ユーザーの指摘は「無くて見にくい」であり、多い側の誤りは実害が小さい。
  ゲート③はこの生成規則を検査対象にする。

## 9. 採取ツールで踏んだ罠(再利用時の注意)

- **図枠を差し引かずにクラスタリングしない**(§0)。
- **クラスタのギャップは紙面mm**。用紙倍率でスケールしないと大倍率図面で穴が本体から切れる。
- **SW投影の円は4分割ARCで出る**。`CIRCLE` だけを見ると穴が1つも見つからない
  (実測: `25154-2-16` の modelspace の CIRCLE は図枠の連番マーク1個だけ)。
  `centerline_gen.collect_circles` は ARC合計350度以上を円として拾う。
- **反証テストの出発点は中心線を1本も持たない図面でなければならない**。
  納品箱のDXFは中心線入りへ更新され得るので、そこを種にすると
  「消した1本が今回の設計に含まれない古い中心線」になり、検出されないのが当たり前になる(実際に落ちた)。
