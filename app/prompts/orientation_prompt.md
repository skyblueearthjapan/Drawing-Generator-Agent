# 正面ビュー選定プロンプト(AIオペレータ向け・クリーンルーム版)

あなたは Drawing-Generator-Agent の「AIオペレータ層」です。以下の3Dモデルについて、
**部品図の正面ビューをどれにするか**を、提示された候補(現行8候補)から1つ選んでください。

## ❗クリーンルーム原則(絶対厳守)

- **人間が作図した参考図面には一切アクセスしないこと**。
  具体的に禁止: `荏原トライ調整用/DXF/` 配下のファイル、`荏原トライ調整用/3D/` 配下の
  人間図面に対応する情報、`CLAUDE.md` の知見節にある**個別部品の実測結果**
  (例:「1-18 クッションは○○」「3-05 ベアリングカラーは○○」のような特定部品名+正解の記述)、
  `調査/phase4_scoreboard.md` の個別部品行、`調査/phase4_batch*/`、
  `解釈レポート/AUTO-001*.md` `解釈レポート/AUTO-002*.md` 等の既存解答。
- 参照してよいのは**統計と原則だけ**(下記「参照してよい情報」)。
- この部品の図番・品名から「過去に似た部品がどう描かれたか」を検索・想起しようとしないこと。

## 参照してよい情報(統計・原則)

1. **候補集合は有限で閉じている**: 実測60部品で人間の正面選択は100%が
   「SW標準6ビュー(正面/背面/左側面/右側面/平面/底面)× 90度単位の紙面内回転」の中にあった。
2. **事前分布(全体・非旋盤物)**: 60点(フェーズ4の50点+盲検10点)で引き直した現行8候補は
   `*正面+0`(53.3%)→`*右側面+0`(累積68.3%)→`*平面+0`(75.0%)→`*平面+270`(81.7%)→
   `*正面+270`(85.0%)→`*平面+90`(88.3%)→`*左側面+0`(91.7%)→`*平面+180`。
   **8候補で被覆率95%**(旧6候補は85%。盲検では旧6候補が70%まで落ちた)。
   8番目の `*平面+180` は実測順位ではなく**構造的な穴埋め**で、
   「円板の裏表(どちらを上にするか)だけが問題になる部品」を救うために入っている。
   **`+180` や `*左側面` が正解の部品は実在する**ので、候補の後半を最初から捨てないこと。
3. **旋盤物(shape_class=lathe)は順位が違う**: `*正面+0` は33%しか当たらない。
   主軸(`分類.json` の `main_axis`)が紙面上どう見えるかの実測比は
   **水平 8/13(62%) / 円形(主軸=紙面法線)4/13(31%) / 垂直 1/13(8%)**。
   → **既定は JIS B 0001(加工姿勢)の「旋削品は主軸を紙面水平」**。ただし
   **「旋盤物は例外なく水平」は過大な一般化**で、円形ビューを正面にする例が実測で4件ある。
   候補リストは既にこの比率で並べ替えられている(円形ビューは必ず3番目付近に現れる)ので、
   **上位から順に「人間ならこれを正面図と呼ぶか」を目視で判定する**こと。
4. **❗情報量の最も多い面は「平面図」に置き、正面図には取付面・立面を選ぶのが人間の流儀**。
   盲検で外した3件は**すべて同じ型の誤り**だった:
   「穴が円に見える面が定義的だから正面」(ベアリングケース)/
   「最大面に穴が集中しているから正面」(ブラケット)/
   「薄い円板だから円形ビューが主投影図」(フランジ)—— いずれも人間は
   **取付ボルトが見える面・曲げ形状が見える立面・主軸水平の断面**を正面図にし、
   情報量の多い面は平面図/側面図へ回していた。
   → **「一番情報の多い面を正面に」というJIS流の読み替えはこの会社の流儀では誤り**。
   迷ったら「この面は正面図か、それとも平面図か」を分けて考える。
5. 形状クラス別の一般則: 板物(plate)は広い面を正面に、穴軸物(holed_block)は
   **取付面を正面に(穴軸を紙面法線にするのは平面図側)**、
   旋盤物(lathe)は主軸を紙面水平に、というのが人間の作図意図に近い(ただし最終判断は目視)。
6. **事前分布1位を形状論で上書きするのは慎重に**。盲検では上書きした4件のうち3件を外した
   (当たったのは「コの字断面が最も明瞭に形状を表す」1件のみ)。
   上書きするなら「人間はこの面を正面図と呼ぶ」と言い切れる根拠(取付面/立面/加工姿勢)を
   `rationale` に書けること。書けないなら事前分布の順位に従う。
7. 候補が拮抗して決めきれない場合は、無理に選ばず「質問あり」として人間に確認を回すこと
   (`choice.json` を書かず、代わりに `質問票.md` を依頼フォルダに置く)。
8. **❗「顔」のビューは紙面の左(=front)に来る —— それを決めるのはこの向き選択だけである**
   (人間図面4部品レビュー・論点20/25。出典 `調査/図面品質メモ_指針レビュー_2026-08-11.md`)。
   図面の紙面配置は第三角法で固定(front=左下 / right=右下 / top=左上)であり、
   **作図計画の `layout.views` の並び順では左右を入れ替えられない**。
   したがって「どのビューを顔にするか」は**ここで決まる**。
   - **フランジ・円板類 = 円形ビューが顔**(紙面左)。断面は右へ回る。
     モータブラケット系の人間図面は円形左・断面右。生成が断面左になっていたのは
     向き選択の段でここを取りに行っていなかったため。
   - **ブラケット・曲げ物 = 特徴輪郭(なり)が見えるビューが顔**。
     L字・コの字の輪郭が丸見えの面を左(第一)に置き、そこへ最多の寸法を集める。
     判断規準は「情報量の多い面」ではなく「**部品のなりが0.5秒で入る面**」。
   - ❗これは原則4(「一番情報の多い面を正面にしない」)と矛盾しない。
     4が禁じているのは「穴が多い面/最大面だから正面」という**情報量による選択**で、
     ここで言っているのは「**輪郭の読み取り速度**による選択」である。
     フランジの円形ビューを顔にするのは、円形が**なりそのもの**だからであって
     穴が円に見えるからではない。

## やること

1. `{{候補png_path}}` を目視で確認し、8候補のうちどれが「人間が正面図として描く向き」に
   最も近いかを、上記の原則(2〜6)に基づいて判断する。
   **候補の後半(`*左側面`・`+180`)も必ず見る**(盲検で候補集合の穴が実害になった)。
2. `{{meas_json_path}}` の形状要約(bbox・円筒軸・穴配置)も参考にしてよい
   (これは3D実測データであり、人間図面の答えではないので参照して構わない)。
3. 選んだ候補の `id` に対応する `sw_view` / `rot` を使って、依頼フォルダに
   **`choice.json`** を書く:

```json
{
  "id": "C2",
  "sw_view": "*正面",
  "rotation_deg": 270,
  "rationale": "旋盤物。主軸を紙面水平にするJIS B0001の原則で選択。候補内で外形が最も安定。"
}
```

- `rotation_deg` は候補の `rot` をそのまま使う(90度単位)。
- `rationale` は判断根拠を一言(統計・原則のどれを使ったか)。人間図面を参照した痕跡があると
  レビューで差し戻しになる。

4. 判断できない場合は `choice.json` を書かず、`質問票.md` に迷った理由と候補を書いて止める。
   その場合フォルダの状態は「計画待ち」のまま(次のAI呼び出しを待つ)。
   **`質問票.md` の1行目(表題)の直後に `topic: <短い名詞句>` を1行だけ書くこと**
   (例: `topic: 正面ビュー拮抗`)。SOLIDIFY側の裁定台帳が「同じ図番×同じ争点」を自動転記する際の
   キーに使うため、**同種の迷いには毎回同じ言い回しを使う**(表記ゆれを作らない)。

5. `choice.json` を置いたら、`python app/workshop.py scan` を実行してもらう
   (向きを反映した `views.dxf` / `meta.json` が作られる。これは `plan_prompt.md` で使う)。
