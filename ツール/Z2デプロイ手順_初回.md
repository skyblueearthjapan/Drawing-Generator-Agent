## 3. gen_py(makepy)の確認

Z2で SolidWorks が起動している対話セッションから:
```powershell
ssh z2 "python -c `"import win32com.client as w; w.gencache.EnsureModule('{83A33D31-27C5-11CE-BFD4-00400513BB57}',0,29,0); print('OK')`""
```
`OK` が出れば `sldworks.tlb` の makepy 済み。失敗する場合は SW2021 起動中に
`python -c "import win32com.client; win32com.client.Dispatch('SldWorks.Application.29')"`
等で一度触れてから makepy し直す(gen_py は初回アクセス時に自動生成されることが多い)。
**`engine/sw_compat.py` の `gen_module()` は候補版を順番に試すので、通常はこの手順を
明示的に踏まなくても検証点①(次章)が自動的にやってくれる。**

## 5. 差分更新(2回目以降・参考)

```powershell
# Z2側の現在コミットを確認
ssh z2 "git -C C:/workshop/Drawing-Generator-Agent rev-parse --short HEAD"
# それを -SinceCommit に渡す
.\ツール\make_z2_bundle.ps1 -Mode Update -SinceCommit <上のコミット> -Push
```
- 差分コミットが0件なら「Z2側は既に最新」の警告を出して**bundleを作らず終了する**
  (`exit 0`。異常ではない)。
- `-Push` は bundle作成 + `scp` + **退避ブランチ `z2-snapshot-<日付>` の作成**まで自動実行する。
  **`fetch`+`merge --ff-only` は表示されたコマンドを人間が実行する**(§2.4/§2.6の
  「実行中ジョブ0確認」を挟むため)。
- ff適用後、常駐(app/worker)の再起動が必要な変更なら **§2.4の見張りタスク経由**で
  再起動する(SSHから`Start-Process`しない。殺して`SOLIDIFY-Watchdog`の蘇生を待つ)。
  このリポジトリ(部品図作成agent)自体は常駐プロセスを持たないので、通常は
  SOLIDIFY側ワーカーの再起動だけが必要になる(統合後、M3以降の話)。

## 6. うまくいかない時のチェックリスト

| 症状 | 確認箇所 |
|---|---|
| `ssh z2` が通らない | `~/.ssh/config` の `z2` エントリ。鍵認証(パスワード不要のはず) |
| `git clone` が文字化けエラー | 日本語ファイル名はbundle経由なら問題ない実績。tarは使わない(§2.3) |
| スパイクの①が失敗(接続不可) | SolidWorksが対話セッションで起動していない。SSH非対話からはCOMを掴めない(§2.5) |
| スパイクの②が失敗(LoadFile4) | サンプルSTEPが正しく転送されているか(`ツール/sample/1-18.STEP`のバイト数比較) |
| スパイクの⑧が失敗(DXF出力) | `GetUserPreferenceStringValue(10)`(図面テンプレート)がZ2側で設定されているか |
| スパイクの⑨で「差分が残っている」 | ❗**最重要**。他のユーザー文書に影響した疑いがある。即座に人間へ報告し、
  Z2で開いているSolidWorksの状態を目視確認してもらう(絶対に自動で何かを閉じにいかない) |
